# Сервис авторизации

## Описание

Сервис авторизации реализует систему аутентификации и управления доступом для приложения.

## Основные компоненты

### 1. Система токенов
- Используется `async-fastapi-jwt-auth` для работы с access и refresh токенами

### 2. Устойчивость к высоким нагрузкам
- Оптимизированная схема базы данных
- Оптимизация запросов к БД
- Использование кэширования

### 3. Хранение данных пользователя
**База данных:** PostgreSQL через ORM SQLAlchemy + asyncpg

#### Модель пользователя
Хорошей практикой считается переопределить стандартную модель пользователя и вынести пользовательскую информацию в отдельную модель. В первую очередь это информация о самом пользователе:
- id
- логин
- пароль
- другая информация о пользователе

#### История аутентификаций
Хранить историю входов пользователя. Это позволит обнаружить подозрительную аутентификацию, например, с нового устройства, которое ему не принадлежит. Минимальный набор для хранения истории аутентификаций:
- id
- user_id (связь с таблицей пользователей)
- user_agent, или более подробный fingerprint
- дата аутентификации
- другая информация о входе

### 4. Хранение токенов
- **Redis** (`redis-py`) — для быстрого поиска по ключу и управления временем жизни данных

## Технологический стек

### ORM для PostgreSQL
- **SQLAlchemy** — самая популярная ORM для работы с реляционными БД на Python. Поддерживает SQLite, PostgreSQL, MySQL, Oracle и Microsoft SQL Server
- ~~**Peewee** — менее известная, но не менее прокачанная ORM для реляционных БД. Поддерживает SQLite, PostgreSQL и CockroachDB~~
- ~~**Pony** — ORM с расширенной поддержкой. Поддерживает SQLite, PostgreSQL, MySQL, Oracle и CockroachDB~~

### Другие библиотеки
- **Alembic** — инструмент для работы с миграциями для SQLAlchemy
- **redis-py** — библиотека для работы с Redis
- **async-fastapi-jwt-auth** — библиотека для работы с JWT-токенами
- **Typer** — библиотека для создания консольных команд (для миграций и управления администраторами)
- **passlib** — средство для работы с паролями пользователей

## Миграции
- Используется Alembic для управления миграциями базы данных


## API для сайта и личного кабинета (`/api/v1/auth`)

| Метод | Эндпоинт | Описание |
|-------|----------|----------|
| `POST` | `/register` | Регистрация пользователя |
| `POST` | `/login` | Вход (возвращает access + refresh токены) |
| `POST` | `/refresh` | Обновление access-токена (ротация) |
| `POST` | `/logout` | Выход (удаляет refresh-токен из Redis) |
| `POST` | `/logout-all` | Выход из всех устройств (сессий) |
| `GET` | `/profile` | Получение данных о себе |
| `PUT` | `/profile` | Обновление `full_name` (email изменить нельзя) |
| `POST` | `/change-password` | Изменение пароля |
| `GET` | `/history` | История входов в аккаунт (страничная загрузка) |

### Основные операции
1. Регистрация пользователя
2. Вход пользователя в аккаунт (обмен логина и пароля на пару токенов: JWT-access токен и refresh токен)
3. Обновление access-токена
4. Выход пользователя из аккаунта
5. Изменение логина или пароля (без дополнительных подтверждений)
6. Получение пользователем своей истории входов в аккаунт
7. Обработка ошибок (истекший токен, неверная подпись, имя пользователя занято)
8. Консольная команда для создания суперпользователя, которому всегда разрешено делать все действия в системе

## API для управления доступом (RBAC) (`/api/v1/idm`)

| Метод | Эндпоинт | Описание |
|-------|----------|----------|
| `POST` | `/roles` | Создать роль |
| `GET` | `/roles` | Список всех ролей |
| `PUT` | `/roles/{role_id}` | Обновить роль |
| `DELETE` | `/roles/{role_id}` | Удалить роль |
| `POST` | `/users/{user_id}/roles` | Назначить роль пользователю |
| `DELETE` | `/users/{user_id}/roles/{role_id}` | Снять роль у пользователя |
| `POST` | `/users/{user_id}/permissions/check` | Проверить наличие права у пользователя |

### Операции управления ролями
1. CRUD для управления ролями:
   - создание роли
   - удаление роли
   - изменение роли
   - просмотр всех ролей
2. Назначить пользователю роль
3. Отобрать у пользователя роль
4. Метод для проверки наличия прав у пользователя (рекомендуется использовать кэширование для производительности)
5. Для реализации ограничения по фильмам предусмотреть присвоение им метки (требует доработки ETL-процесса)

## Дополнительные возможности

### Выход из всех устройств
Реализована кнопка «Выйти из остальных аккаунтов» без хранения в БД активных access-токенов.
